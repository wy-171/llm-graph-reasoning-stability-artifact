# Observable-trace screening set

This directory contains the separate descriptive screening set reported in the manuscript's observable-trace illustration. It is distinct from the focused v6A paired panel in the repository root.

## Design

- Graphs A–D: 5 separately submitted fresh-context calls per model–graph cell
- Graphs E–H: 3 separately submitted fresh-context calls per model–graph cell
- Models: Claude Sonnet 4.6, Mistral Large 2512, and DeepSeek V3.2 Exp
- Total: 96 successful OpenRouter API calls collected on August 13–14, 2026 (UTC)
- Provider routes: Anthropic, Mistral, and SiliconFlow, respectively
- Provider fallbacks: disabled
- Temperature: omitted from the request; applied provider defaults were not independently verified

The screening was descriptive. Trace labels were assigned retrospectively by one coder and distinguish exhaustive enumeration, distance-update or Dijkstra-style reasoning, and their execution order. They are not a validated annotation scale and were not used to calculate a numerical trace-stability score.

## Manuscript cross-check

For Graph A under Claude Sonnet 4.6, the five coded sequences are `D→E`, `E→D`, `D`, `D`, and `E→D`, where `D` denotes distance-update or Dijkstra-style reasoning and `E` denotes exhaustive enumeration. This yields the reported split of one Dijkstra-then-enumeration run, two enumeration-then-Dijkstra runs, and two primarily Dijkstra-based runs. All 96 calls were HTTP 200 and were coded as returning the exact minimum-weight path set, weights, and edge counts.
