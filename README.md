# Reproducibility artifact: repeated-run stability in LLM graph reasoning

This repository contains the data and code for the focused v6A API pilot on repeated-run answer stability in graph reasoning. The study compared two separately submitted fresh-context runs with byte-identical prompts (`ES1` and `ES2`) and two diagnostic oracle conditions (`ORACLE_BASE` and `ORACLE_EDGE`).

## Study snapshot

- 20 collection blocks and 140 pre-generated task slots
- 4 conditions per slot, for 560 planned calls
- 558 completed calls and 2 calls that failed after three HTTP 429 responses
- 480 focal-model calls (Mistral Large 2512) and 80 secondary-model calls (Claude Sonnet 4.6 and DeepSeek V3.2 Exp)
- Three graph conditions: M2, M4, and M8
- Schedule seed: `20260815`
- API sampling parameters such as temperature, top-p, maximum tokens, and decoding seed were omitted from the request body

`ES1` was always submitted first within a slot. The order of `ES2`, `ORACLE_BASE`, and `ORACLE_EDGE` was randomized according to the frozen manifest. `ORACLE_BASE` supplied the complete tied candidate set without edge counts; `ORACLE_EDGE` supplied the same candidates and also displayed edge counts.

## Reproduce the reported summaries

Python 3.9 or later is sufficient; the analysis has no third-party dependencies.

```bash
python3 analysis/reproduce_results.py
```

The command validates the row counts and manuscript-level numerical checks before replacing the CSV and text files in `results/`. It reports answer distributions, pooled and condition-specific stability statistics, paired risk differences with 5,000-replicate block-cluster bootstrap intervals (seed 1), exact two-sided McNemar tests, graph-level accuracy, and secondary-model accuracy.

The preserved collection script can also print its original diagnostic summaries, but it expects the data files in its working directory and imports the adjacent graph module. The supported reproduction path for this repository is `analysis/reproduce_results.py`; running the collection code would make new paid API calls and would not recreate the original responses.

## Scope

This release is limited to the focused quantitative v6A panel and the materials needed to audit and reproduce its reported results. Earlier exploratory rounds, unrelated test sets, working backups, and other project data are excluded.

See `docs/PROVENANCE.md` for the two collection-code hashes recorded in the call-level data and the unavailable earlier source snapshot.
